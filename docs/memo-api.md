# 메모 API 연결

[Swagger](https://api-gotrip.prot.kr/swagger-ui/index.html)의 `/memo` API에 맞춰 목록·상세·생성·수정·삭제를 연결했습니다. 채팅과 동일한 로그인 토큰을 사용하며 더미 메모는 표시하지 않습니다.

## 사용

```sh
npm run dev
```

`/memo`에서 로그인하기를 누르면 로그인 성공 후 메모 화면으로 돌아옵니다. + 버튼은 작성 중인 새 메모를 만들고, **메모 저장** 버튼을 누를 때 서버에 생성합니다. 제목과 본문이 함께 저장되며 본문은 앞뒤 공백을 제외하고 최소 5자여야 합니다. 본문에서 Ctrl/Cmd+Enter로도 저장할 수 있습니다.

저장 전 입력은 다른 메모를 선택했다 돌아와도 화면에 유지됩니다. 새로고침이나 페이지 이동 전에는 저장해 주세요. 전송 실패 시 작성한 내용을 유지하고, 서버 삭제가 성공한 경우에만 목록에서 제거합니다. 저장·삭제 중 중복 요청을 막습니다. 로그인 만료 시 입력을 유지하고 재로그인 링크를 표시합니다.

제목·본문과 한줄 요약은 서로 독립적으로 편집하고 저장합니다. 본문 입력으로 요약을 만들지 않으며, 오른쪽 목록에는 본문 대신 **저장된 한줄 요약만** 표시합니다. 요약을 입력한 다음 오른쪽 **저장** 버튼(또는 Enter)을 누르면 목록에 반영됩니다. 새 메모는 먼저 **메모 저장**을 눌러 서버에 생성해야 요약도 저장할 수 있습니다. 빈 요약을 저장하면 목록의 요약을 지웁니다.

서버 명세에는 요약 필드가 없어 한줄 요약은 현재 브라우저의 `localStorage`에 계정·메모 ID별로 별도 저장합니다. 새로고침과 재로그인 후에도 같은 계정이면 유지되지만, 다른 브라우저·기기와 동기화되지 않으며 브라우저 데이터를 지우면 사라집니다. 저장 공간 오류가 나면 입력과 이전에 저장된 요약을 유지합니다. 본문 저장 요청에는 요약을 섞거나 미지원 필드를 추가하지 않습니다. 서버에서 요약을 공유하려면 메모 API에 별도 요약 필드가 필요합니다.

검색은 현재 목록의 제목·본문·저장한 요약을 대상으로 하며 여러 단어를 모두 포함하는 메모를 찾습니다.

## API

| 기능 | 요청 | 성공 응답 |
| --- | --- | --- |
| 목록 | `GET /memo` | `MemoResponse[]` |
| 상세 | `GET /memo/{id}` | `MemoResponse` |
| 생성 | `POST /memo/new` | 숫자 메모 ID |
| 수정 | `PUT /memo/edit/{id}` | 본문 없는 200 허용 |
| 삭제 | `DELETE /memo/delete/{id}` | 본문 없는 200/204 허용 |

생성·수정 요청은 서버 필드명인 `content`를 사용합니다. 화면의 `body`와 `content` 변환은 `src/services/memoApi.js`에서 담당합니다.

```json
{ "title": "제주 여행", "content": "첫째 날은 바닷가 방문하기" }
```

```json
{
  "id": 12,
  "title": "제주 여행",
  "content": "첫째 날은 바닷가 방문하기",
  "createdAt": "2026-10-27T12:00:00Z",
  "updatedAt": "2026-10-27T12:00:00Z"
}
```

생성은 ID 하나만 반환하므로 제출한 데이터와 반환 ID를 합쳐 목록에 반영합니다. 생성한 메모를 선택하면 상세 조회로 서버 데이터를 확인합니다. 수정·삭제는 성공 응답에 JSON 본문이 없어도 처리합니다. 401 응답은 공통 클라이언트가 토큰을 제거하고, 403·404·서버 오류는 화면에 표시합니다. 상세 조회는 선택 변경이나 페이지 종료 시 취소해 뒤늦은 응답이 다른 메모를 덮어쓰지 않도록 합니다.

## 프록시와 배포

개발 중 메모 요청은 `/backend/memo…`로 보내고 Vite가 `/backend`를 제거해 `VITE_API_BASE_URL` 서버로 전달합니다. 환경변수가 없으면 `https://api-gotrip.prot.kr`가 대상입니다. 이 경로를 분리해야 프런트엔드 `/memo` 화면과 백엔드 목록 API가 충돌하지 않습니다. 기존 `/api` 채팅·로그인 프록시는 그대로 사용합니다.

빌드 결과물에서는 `VITE_API_BASE_URL`이 있으면 해당 주소의 `/memo…`로 직접 요청합니다. 이때 서버에서 프런트엔드 origin, `Authorization`·`Content-Type`, `GET`·`POST`·`PUT`·`DELETE`·`OPTIONS`의 CORS를 허용해야 합니다.

`VITE_API_BASE_URL`을 비워 같은 origin으로 배포할 때는 웹 서버에서 `/backend/`를 API 서버로 프록시하고 접두사를 제거하세요. 로그인·채팅의 `/api/`도 프록시해야 하며, 화면 주소 `/memo`는 SPA의 `index.html`로 연결해야 합니다. Vite 개발 프록시는 정적 배포에 포함되지 않습니다.

## 검증

```sh
npm test
npm run build
```

`tests/memoApi.test.js`와 `tests/memoSummary.test.js`에서 계정별 독립 요약 저장·새로고침·실패 보존과 실제 Swagger 형태의 응답을 주입해 경로·메서드·인증·요청 본문·숫자 생성 응답·빈 수정/삭제 응답·입력 검증·검색·실패와 취소 처리를 검증합니다. 실제 계정의 생성·수정·삭제는 로그인 후 확인해야 합니다.
