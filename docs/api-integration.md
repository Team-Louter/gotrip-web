# Swagger 전체 API 연결

기준: 2026-10-28 조회한 [운영 Swagger](https://api-gotrip.prot.kr/swagger-ui/index.html)의 15개 요청입니다. 친구 목록을 가장 먼저 연결했고 기존 로그인·채팅·메모 화면에 일정 등록과 장소 추가·삭제를 연결했습니다.

## 연결 현황

| 우선순위·기능 | 요청 | 연결 화면 / 코드 |
| --- | --- | --- |
| 1. 친구 목록 | `GET /api/members` | 채팅 + 버튼의 전체 사용자 목록 · `memberApi.js` |
| 회원가입 | `POST /api/members/signup` | 회원가입 3단계 · `authApi.js` |
| 로그인 | `POST /api/members/login` | `/islogin` · `authApi.js` |
| 채팅방 목록 | `GET /api/chat/rooms` | `/chat` · `serverChatApi.js` |
| 채팅방 생성 | `POST /api/chat/rooms` | 채팅방 생성 창의 서버 채팅 · `serverChatApi.js` |
| 메시지 조회 | `GET /api/chat/rooms/{roomId}/messages` | `/chat/:roomId` · `serverChatApi.js` |
| 메시지 전송 | `POST /api/chat/rooms/{roomId}/messages` | `/chat/:roomId` · `serverChatApi.js` |
| 메모 목록 | `GET /memo` | `/memo` · `memoApi.js` |
| 메모 상세 | `GET /memo/{id}` | 메모 선택 · `memoApi.js` |
| 메모 생성 | `POST /memo/new` | 메모 저장 · `memoApi.js` |
| 메모 수정 | `PUT /memo/edit/{id}` | 메모 저장 · `memoApi.js` |
| 메모 삭제 | `DELETE /memo/delete/{id}` | 메모 목록의 삭제 · `memoApi.js` |

| 장소 삭제 | `DELETE /schedule/map/{placeId}` | `/map`의 삭제 / 장소 ID로 삭제 · `tripApi.js` |

## 친구 목록 우선 연결

별도 친구 화면은 제거하고 `/friends`는 `/chat`으로 이동합니다. 채팅 + 버튼에서 `/api/members`의 전체 사용자를 받고 본인도 포함합니다. 체험 채팅의 받는 사람은 기본 전체 선택되며 닉네임·아이디로 검색할 수 있습니다. 현재 운영 서버는 로그인 전에도 이 조회를 허용하며, 로그인한 경우에는 기존 인증 토큰을 전달합니다. 채팅방 생성 창도 같은 회원 목록을 사용합니다.

이 API는 이름이 ‘전체 회원 조회’이며 친구 관계를 맺거나 수락·차단하는 API는 없습니다. 현재 응답은 다음 형태로 **숫자 회원 ID가 없습니다**.

```json
[{ "loginId": "minji", "nickname": "김민지" }]
```

채팅방 생성은 `memberIds: [숫자 ID]`를 요구합니다. 따라서 회원 ID가 없는 친구는 선택 초대를 비활성화합니다. 숫자 ID 직접 입력란과 친구별 채팅 바로가기 버튼은 제공하지 않습니다. 목록 인덱스나 로그인 아이디에서 회원 ID를 만들지 않습니다. 브라우저 체험방에서는 모든 사용자를 수신자 테스트 대상으로 선택할 수 있습니다. 실제 서버 초대는 응답에 `id` 또는 `memberId`가 제공되는 경우에만 연결합니다. 선택한 친구가 없으면 생성 버튼은 비활성화됩니다. 백엔드가 회원 ID를 제공해야 현재 서버에서 친구 선택 초대를 사용할 수 있습니다.

## 일정 등록 범위

서버 요청은 `{ "hour": 9, "minute": 5, "content": "카페에서 점심 먹기" }`입니다. 내용은 앞뒤 공백을 제외하고 5자 이상이며 시간은 0~23시, 0~59분입니다. 날짜 필드가 명세에 없어 선택한 날짜는 브라우저에서만 관리합니다.

새 일정은 서버 성공 후 캘린더·지도 스케줄 공통 목록에 추가합니다. 실패하면 입력을 유지하고, 처리 중 중복 제출·닫기를 막습니다. 등록한 일정과 선택 날짜는 계정별로 브라우저에 보관합니다. 조회 API가 없어 다른 기기나 새 브라우저의 서버 일정을 불러올 수 없습니다. 예제 일정을 서버 데이터처럼 표시하지 않습니다.

일정 수정·삭제 API가 없어 기존 수정은 ‘이 브라우저에서 수정됨’으로 표시하고, 서버 등록 항목의 목록 제거는 ‘숨기기’로 표시합니다. 수정이나 숨기기가 서버 데이터를 변경했다고 안내하지 않습니다. 서버 차원의 날짜 저장·조회·수정·삭제에는 API 추가가 필요합니다.

## 장소 추가·삭제 범위

추가 요청은 `{ "address": "서울시 종로구" }`이고 응답 명세는 문자열입니다. 숫자 ID가 반환되는 경우만 서버 장소 ID로 사용하며, 단순 성공 문장에서 숫자를 추측하지 않습니다. 일반 성공 문자열이면 추가한 주소를 브라우저 목록에 보관합니다. 성공했는데 브라우저 저장만 실패한 경우 서버 성공을 취소한 것처럼 처리하지 않고 저장 경고를 표시합니다.

장소 목록 조회 API가 없어 이 브라우저에서 추가한 주소만 목록에 표시합니다. 서버 ID가 확인된 항목은 삭제 버튼으로 실제 삭제 요청을 보냅니다. ID가 없는 항목의 숨기기는 로컬 목록만 제거합니다. 알고 있는 숫자 장소 ID는 별도의 ‘장소 ID로 삭제’에 입력할 수 있습니다. 추가 응답에 `placeId`가 있고 목록 조회 API도 있어야 다른 기기까지 포함한 조회·선택 삭제를 완결할 수 있습니다.

지도 화면의 배경은 기존 이미지이며, 장소 검색·좌표·길찾기·지도 SDK API는 Swagger에 없습니다. 정산 API와 메모 요약 필드도 명세에 없어 기존 로컬 동작을 유지합니다.

## 인증·프록시·검증

`.env.example`의 운영 주소를 사용합니다. `/api/…`는 기존 개발 프록시, `/calendar`, `/memo`, `/schedule/…`는 화면 주소와 충돌하지 않도록 `/backend/…`로 요청한 뒤 접두사를 제거하는 프록시를 사용합니다. 배포 시에는 `VITE_API_BASE_URL`로 직접 요청하거나 같은 origin에서 `/api` 및 `/backend` 역방향 프록시를 구성해야 합니다.

로그인 토큰은 공통 `sessionStorage`를 사용하고 401 응답 시 제거합니다. 회원가입 비밀번호는 Swagger와 동일하게 8~20자, 문자 종류 4종 중 3종 이상, 동일 문자 3회 연속 금지 규칙을 적용합니다. 마케팅 약관은 선택이며 필수 개인정보 약관 동의로 가입할 수 있습니다.

```sh
npm test
npm run build
```

친구·초대 ID 누락, HTTP 메서드·본문·인증, 일정 시각 변환, 장소 응답의 ID/성공 문자열 구분, 저장 실패와 취소, 계정별 브라우저 보관을 테스트합니다. 실제 서버의 친구 목록 조회를 확인하며, 데이터 변경은 실제 계정 정보를 요구하므로 자동 브라우저 검증에서는 Swagger 형태의 응답을 주입해 15개 요청이 화면에서 호출되는지 확인합니다.

## 현재 서버 채팅 테스트 설정

사용자 요청에 따라 채팅 생성 화면은 서버 모드만 사용합니다. 회원 ID가 없는 전체 사용자는 응답 순서대로 1, 2, 3…에 테스트 매핑하여 `memberIds`로 전송합니다. 실제 DB ID 및 수신은 보장하지 않습니다. 기존 브라우저 체험방은 목록에 표시하지 않으며 서버 오류를 로컬 성공으로 대체하지 않습니다. 자세한 내용은 [서버 채팅 문서](chat-api.md)를 참고하세요.
